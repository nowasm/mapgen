# 房间—走廊式地下城地图生成器设计

- 日期：2026-08-13
- 状态：已确认
- 新仓库：`D:\work_mine\modelEditor\mapgen`
- 参考仓库：`D:\work_mine\modelEditor\rpgcobo-tool`

## 1. 目标

复刻 RPG-Cobo 默认 Dungeon Map Generator 的生成风格、结构特征和参数控制能力，
但不要求复现原二进制算法，也不要求相同 Seed 产生相同地图。第一版生成无屋顶、
单层、房间—走廊式的普通模块化三维地牢，供第三人称斜俯视游戏使用。

生成器作为本地网页工具运行。用户只修改参数并重新生成，不进行逐块绘制或房间拖拽。
选定地图后导出可见模型与结构数据，再由 Godot 编辑器插件固定烘焙为可编辑、可碰撞、
角色可行走的 `.tscn` 场景。最终运行时不依赖生成器。

### 1.1 成功标准

- 默认 `160 × 160` 配置可稳定生成 10 个有效候选。
- 同一实现版本中，相同 Seed、参数和资源包产生相同布局。
- 所有房间从出生点可达，且不存在非法房间、墙体或走廊重叠。
- 开门可通行；关门具有碰撞；角色不穿墙、不掉出地板。
- 导出的 GLB 在 Godot 中朝向、比例、模型和材质正确。
- Godot 插件可依据 JSON 创建原生碰撞和出生点并保存 `.tscn`。

### 1.2 第一版不做

- 多层地下城、楼梯、屋顶和室外地形。
- 运行时随机生成和运行时资源转换。
- NavMesh、敌人、战利品、任务或战斗逻辑。
- 动态门、门交互和开关动画；门只烘焙为固定开启或关闭状态。
- 手工刷块、逐体素编辑、拖拽房间和自动室内装饰。
- 与原程序的逐像素或跨实现 Seed 兼容。

## 2. 已验证的原项目背景

参考仓库在 `project/plugin/rpgtools/mapeditor/MapGenerator.sk` 中保留了 Dungeon 参数定义，
但真正生成源图的 `tools/mapimggen.exe` 没有对应源代码。原编辑器一次生成 10 个候选，
选中后再转换为最终地图。因此本项目以可观察行为和公开参数为兼容目标，重新实现算法。

参考仓库包含地牢相关 `.vox` 资源及 `map_vox.json` 映射，包括 `dungeon1.vox`、
`floor1.vox`、`wall1.vox`、`indoor1.vox` 和 `exdoor1.vox`。资源格式和子模型语义需由
离线转换器验证，不假定所有 `.vox` 文件都完全符合某一公开方言。

## 3. 总体架构

```text
参数面板 ──> generator-core ──> DungeonLayout
                                  │
                   ┌──────────────┼──────────────┐
                   │              │              │
                2D 候选      Three.js 预览    结构校验
                                  │
                         dungeon-renderer
                                  │
                  dungeon.glb + dungeon.layout.json
                                  │
                         Godot 导入/烘焙插件
                                  │
       VisualModel + StaticBody3D + CollisionShape3D + Marker3D
                                  │
                            Dungeon.tscn
```

采用单仓库分包结构：

```text
mapgen/
├── apps/web/                     # React、Vite、Three.js 用户界面
├── packages/generator-core/      # 纯 TypeScript 确定性生成算法
├── packages/layout-schema/       # 类型、JSON Schema、版本迁移
├── packages/dungeon-renderer/    # 模块装配、预览和 GLB 导出
├── tools/vox-converter/          # 原资源离线转换工具
├── godot/addons/mapgen_importer/ # Godot 编辑器导入/烘焙插件
├── godot/test-project/           # 导入和角色行走验收工程
├── assets/source/                # 获准迁移的原资源与来源清单
├── assets/generated/             # 转换后的模块包
├── tests/fixtures/               # 固定 Seed 回归数据
└── docs/{plans,adr}/
```

算法包不引用 Three.js、DOM 或 Godot。渲染器只消费版本化的 `DungeonLayout`，Godot
插件只消费导出契约。这使布局算法、网页 UI、美术资源和目标引擎可以分别替换。

## 4. 数据和坐标约定

逻辑布局使用整数 XZ 网格，Y 轴向上。默认一格等于一米。逻辑网格范围为
`x ∈ [0,width)`、`z ∈ [0,height)`；渲染和导出时将地图中心平移到世界原点：

```text
world_x = (grid_x - width / 2) * cell_size
world_z = (grid_z - height / 2) * cell_size
world_y = logical_height * cell_size
```

所有距离和旋转使用米、弧度以及右手坐标约定。GLB 根节点不携带非单位缩放。
模型标准朝向、枢轴点、包围盒和门洞尺寸记录在模块目录中。

`dungeon.layout.json` 至少包含：

```text
schemaVersion, generatorVersion, seed, parameters
grid, coordinateSystem, assetPack
rooms[], connections[], corridors[], doors[]
spawn, modules[], colliders[], diagnostics
```

房间和走廊保留逻辑结构；`modules` 是最终可见模块实例；`colliders` 是 Godot 烘焙所需
的轴对齐盒。数组元素使用稳定 ID 互相引用。Schema 版本使用整数主版本，导入器拒绝
未知主版本，不静默猜测。

GLB 只承载可见模型、PBR 材质和稳定节点名；JSON 承载碰撞与游戏语义。第一版不依赖
glTF GPU 实例化或自定义碰撞扩展。

## 5. 地下城生成算法

采用“图优先 + 约束二维放置”，而不是 BSP 或无约束随机房间。

### 5.1 生成阶段

1. 使用明确版本的伪随机数算法从 Seed 创建随机流。
2. 选择 Hub、Ring 或 Branch 拓扑；Random 按配置权重选择。
3. 先建立主路径，再增加分支、环路和死胡同，得到连通房间图。
4. 分配房间尺寸、功能标签和受保护连接。
5. 在 `160 × 160` 等目标网格内进行有界次数的约束放置。
6. 优先使用直线或 L 形走廊；受阻时以网格寻路避开房间禁区。
7. 在房间与走廊的合法边界生成门，并按概率固定为开启或关闭。
8. 栅格化占用区域，生成地板边界、墙、拐角、门框和碰撞盒。
9. 验证可达性、净空、重叠和边界；失败则丢弃候选并尝试下一 Seed。

### 5.2 拓扑模式

- **Hub**：一个核心房间或核心房间组向外连接多个翼；允许少量翼间捷径。
- **Ring**：主路径形成至少一个环，支路附着于环；入口不必位于环上。
- **Branch**：一条主路径连接多个树状分支，并按 `loopRate` 增加少量回连。
- **Random**：默认以 `0.33 / 0.34 / 0.33` 权重选择 Hub、Ring、Branch。

入口房间、关键主路径和确保拓扑特征成立的边受保护。普通分支默认不能破坏这些结构，
但 `branchFromProtectedChance` 允许受控地从受保护节点继续分支。

### 5.3 参数兼容语义

原版双滑块值表示“先在该区间抽取本次候选的有效值”。所有区间采样也由 Seed 决定。

| 参数 | 可选范围 | 原版默认 | 新实现语义 |
|---|---:|---:|---|
| `size` | 实现限制内 | `[160,160]` | XZ 逻辑网格尺寸 |
| `largeCellSize` | `10..50` | `[22,38]` | 拓扑锚点/大空间的目标间距 |
| `mode` | Random/Hub/Ring/Branch | Random | 拓扑选择或权重集合 |
| `roomRate` | `0..1` | `[0.25,0.5]` | 可用拓扑槽位转成房间的比例倾向 |
| `roomSize` | `0.2..2.0` | `[0.8,1.2]` | 基础房间尺寸的乘数 |
| `roomMinSize` | `6..20` | `[10,14]` | 房间较短边的有效下限 |
| `roomMaxSize` | `18..48` | `[28,36]` | 房间边长的有效上限 |
| `roomCountMin` | `4..12` | `[5,7]` | 候选房间数下限 |
| `roomCountMax` | `10..40` | `[20,28]` | 候选房间数上限 |
| `corridorWidth` | `2..8` | `[4,4]` | 走廊净宽（格） |
| `loopRate` | `0..1` | `[0.2,0.4]` | 合法非树边的添加倾向 |
| `deadEndRate` | `0..1` | `[0.15,0.25]` | 终止分支出现倾向 |
| `branchTryMultiplier` | `0..20` | `[8,12]` | 分支目标数对应的放置尝试预算倍数 |
| `branchFromProtectedChance` | `0..1` | `[0.1,0.3]` | 从受保护主路径节点继续分支的概率 |
| `linearWingChance` | `0..1` | `[0.28,0.38]` | 连续生成近直线房间翼的概率 |
| `mirrorXChance` | `0..1` | `[0.4,0.6]` | 局部结构沿 X 轴近似镜像的概率 |
| `doorOpenRate` | `0..1` | `[0.2,0.8]` | 每个门固定烘焙为开启状态的概率 |

若抽取后出现 `min > max`，在参数验证阶段交换两值并产生警告；超出允许范围则阻止生成。

## 6. 模块化资源管线

### 6.1 离线转换

`vox-converter` 读取获准迁移的 `.vox` 文件和 `map_vox.json` 子模型映射，首先验证格式
版本与调色板，再提取指定地牢模型。转换使用贪心网格合并共面体素面，删除不可见内面，
保留调色板颜色，并生成：

```text
assets/generated/dungeon-kit.glb
assets/generated/dungeon-kit.json
```

模块目录记录来源文件、子模型名、内容哈希、类别、包围盒、标准朝向、枢轴、连接面和标准
尺寸。原文件永不被转换器原地修改。若格式无法识别、映射缺失或模型超限，转换立即失败并
报告具体资源，不生成不完整资源包。

资源迁移前必须核对参考仓库 `LICENSE` 与 `NOTICE.txt`，在新仓库保留要求的许可文本和
逐文件来源清单。设计允许复用不等同于省略归属审查。

### 6.2 第一版模块

- 地板
- 直墙
- 内拐角与外拐角
- 门框
- 开门模型
- 关门模型
- 可选立柱

第一版只转换一套视觉一致的默认地牢资源。墙高默认约 2.5 米，最终数值以选定模块和
角色净空测试为准。地图不生成屋顶。模块可沿轴向重复或按受控规则缩放，但不允许产生
非单位 GLB 根节点。

预览可使用实例化渲染；导出时地板和墙按材质合并为普通静态网格。门保持独立稳定节点。
碰撞使用 JSON 中的简化盒：地板、墙体和关闭门产生碰撞，开启门不产生门板碰撞。

## 7. 网页端工作流

界面分为参数面板、10 个候选缩略图和三维预览区。

1. 用户修改参数或恢复“原版默认”预设。
2. 点击“生成候选”，以一个基础 Seed 和连续派生 Seed 计算 10 个二维布局。
3. 选择候选后才装配完整三维模型，以减少等待和显存占用。
4. 用户可在斜俯视观察与第三人称行走模式之间切换。
5. 调试开关可显示房间图、逻辑占用和碰撞盒。
6. 点击导出，同时下载匹配的 GLB 与 JSON；二者共享 `exportId` 和内容摘要。

支持复制 Seed、同 Seed 重新生成和重新选择候选。参数发生改变后，旧预览和导出按钮标记
为过期，直到重新生成，避免导出 UI 参数与实际布局不一致的文件。

Rapier 只用于网页端行走预览。Godot 生成的碰撞才是最终交付物的权威结果。

## 8. Godot 导入与固定烘焙

Godot 插件提供编辑器面板或文件入口，用户选择同一次导出的 GLB 与 JSON。插件执行：

1. 验证 Schema、`exportId`、内容摘要、坐标约定和资源包 ID。
2. 实例化 Godot 已导入的 GLB 场景。
3. 依据 `colliders` 创建 `StaticBody3D` 与 `CollisionShape3D`。
4. 依据 `spawn` 创建带稳定名称的 `Marker3D`。
5. 将门保留为可识别子节点，并按 JSON 创建或省略门板碰撞。
6. 生成元数据节点/资源，记录 Seed、参数、Schema 和生成器版本。
7. 保存为用户指定路径下的 `Dungeon.tscn`。

插件不会在运行时重新生成，也不会把碰撞烘进 GLB。重复烘焙默认创建/覆盖由插件管理的
新场景；如果目标场景存在用户编辑，插件必须要求选择新路径或显式确认，不能静默删除。

目标树结构：

```text
DungeonRoot
├── VisualModel
├── Collision
│   └── StaticBody3D
│       └── CollisionShape3D...
├── Doors
├── PlayerSpawn
└── DungeonMetadata
```

## 9. 错误处理与安全边界

### 9.1 生成失败

每个候选的房间放置、走廊寻路和修复都有有限预算。失败候选使用下一派生 Seed 重试，
但批次也有总预算。超过预算后返回结构化诊断，例如：

- `ROOM_PLACEMENT_EXHAUSTED`
- `CORRIDOR_ROUTE_FAILED`
- `DISCONNECTED_GRAPH`
- `CLEARANCE_VIOLATION`
- `MAP_BOUNDS_EXCEEDED`

系统不导出验证未通过的布局，也不无限重试。

### 9.2 文件与插件安全

- 网页生成器为纯本地客户端，不上传地图、Seed 或资源。
- JSON 导入前使用 Schema 校验，并限制地图尺寸、数组长度、字符串长度和文件大小。
- 插件只在用户选择的项目路径内生成文件，不接受 JSON 提供的任意输出路径。
- GLB 和 JSON 必须通过 `exportId` 与摘要匹配。
- 外部资源 URI、未知 Schema 主版本和非有限浮点数一律拒绝。
- 资源转换输出写入独立目录，绝不覆盖参考仓库源文件。

## 10. 非功能目标

- **确定性**：随机算法和迭代顺序版本化；禁止依赖对象键的偶然遍历顺序。
- **性能**：默认地图的 10 个二维候选应在普通开发机上数秒内完成；只为选中候选建立 3D。
- **可维护性**：TypeScript 开启严格模式；核心数据通过 Schema 和包级 API 通信。
- **可移植性**：支持当前主流 Chromium/Firefox；Godot 插件以 Godot 4 稳定版 API 为目标。
- **离线性**：构建完成后的工具不依赖云服务、账户、数据库或遥测。
- **规模限制**：第一版以 `160 × 160` 为性能基线，不为超大开放世界提前设计。
- **可恢复性**：导出为普通文件；固定 Seed、参数和资源包版本足以复现布局。

## 11. 测试与验收

### 11.1 自动测试

- 随机数与相同 Seed 确定性测试。
- 每个参数的最小、最大、固定区间和非法组合测试。
- 图连通性、Hub/Ring/Branch 特征和环/死胡同比例统计测试。
- 房间不重叠、走廊净宽、地图边界、门位置和出生点可达属性测试。
- `DungeonLayout` JSON Schema 往返与未知版本拒绝测试。
- 模块包枢轴、朝向、包围盒和资源哈希测试。
- GLB/JSON 配对测试。
- Godot 无界面导入冒烟测试：生成 `.tscn`、节点类型和碰撞数量正确。

### 11.2 固定回归样本

为每种拓扑保存多组固定 Seed 的布局摘要、诊断和预览图。算法有意改变时更新生成器版本，
并由评审者确认回归样本变化，避免无意漂移。

### 11.3 人工验收

- 在网页端用第三人称角色走遍开启连通区域。
- 在 Godot 测试工程导入并以相同角色控制器复测。
- 检查墙角、窄走廊、L 形拐角、门洞和地图边缘。
- 在 Godot 编辑器中选中并修改生成的碰撞节点，确认场景可编辑。

## 12. 分阶段交付

### 阶段 1：最小端到端切片

以程序化占位方块生成一个最小房间—走廊地图，导出 GLB/JSON，并由 Godot 插件烘焙为
带碰撞和出生点的 `.tscn`。先验证坐标、比例、Schema 和导入边界。

### 阶段 2：完整布局与网页工作流

实现图优先算法、全部确认参数、10 个候选、二维缩略图、三维观察及结构验证。

### 阶段 3：原资源转换

完成许可和来源清单、`.vox` 方言验证、地牢模块提取、网格优化和默认资源包替换。

### 阶段 4：行走预览与质量收尾

加入 Rapier 第三人称验证、调试叠层、性能优化、固定 Seed 回归和完整 Godot 验收。

## 13. 主要风险与缓解

| 风险 | 影响 | 缓解 |
|---|---|---|
| `.vox` 是定制方言或包含复杂子模型 | 资源转换延期 | 阶段 1 使用占位模块；转换器先做格式探测和小样本验证 |
| 合并网格后材质或枢轴错误 | Godot 中错位 | 模块目录保存标准朝向；设置单模块黄金测试 |
| 图拓扑可行但空间放置失败率高 | 候选生成慢或失败 | 有界重试、逐级降级、候选诊断和默认参数统计测试 |
| Three.js 与 Godot 物理结果不同 | 网页可走、Godot 不可走 | 两端使用同一简化碰撞盒；Godot 为权威验收 |
| GLB 与 JSON 被错误配对 | 模型与碰撞错位 | `exportId`、摘要、Schema 和资源包 ID 联合校验 |
| 原资源许可归属在迁移时丢失 | 无法合规分发 | 复制前审查；保留 LICENSE、NOTICE 和逐文件来源清单 |
