# Kenney Building Kit 模块化地牢迁移设计

## 目标

将地图生成器的默认视觉底座切换为 `assets/kenney_building-kit`。布局继续支持任意单层房间尺寸、走廊宽度、门位和拓扑；视觉层只使用独立墙、转角、地板、门框和门扇拼装，不再依赖固定房间模型。生成结果仍可导出 GLB，并保留语义碰撞体供 Godot 导入。

## 方案

采用 Kenney Building Kit 的 2 米原生模数：普通地板和直墙按 2 米重复，末端不足 2 米时仅缩放最后一个槽位。全局 `roomCornerStyle` 可选择 `column`、`diagonal` 或 `round`，分别使用 `wall-corner-column`、`wall-corner-diagonal`、`wall-corner-round`；后两者搭配相应角落地板，中间区域用普通地板补齐。直墙从转角切点开始铺设，真实门位对应的槽位由门框替换，因此不会出现墙体穿过门洞。

门型不再随机：`column` 房间固定使用方形 C 型门，`diagonal` 与 `round` 房间固定使用圆形 C 型门。无论走廊多宽，都使用原始尺寸的 2 米窄门框和单片 C 型门扇；门框两侧及上方由墙段闭合，不拉伸门模型。门扇关闭时按原始尺寸生成碰撞，开启时以侧边门轴为基准向所属房间内部旋转，且不生成门扇碰撞。

## 数据流

1. `generator-core` 生成任意偶数尺寸房间，并根据房间角落样式确定唯一门型。
2. `build-modules` 将房间边界分解为 2 米墙槽、四个转角、地板区域和门模块，同时生成匹配的盒形/分段圆弧碰撞体。
3. 资源构建脚本从 OBJ 和 colormap 生成自包含的顶点色视觉包。
4. `dungeon-renderer` 根据 `assetKey` 选择 Building Kit 原型并输出 Three.js 场景与 GLB。
5. Godot 固定样例同时导入 GLB 与布局 JSON，验证资源标识、节点和碰撞体数量。

## 失败处理与约束

- 资源构建脚本缺少 OBJ、MTL、纹理或许可证时直接失败，不静默退回旧资源。
- 圆角半径固定为 Building Kit 原生 2 米模块；过小房间仍受现有最小尺寸参数保护。
- 碰撞体按语义几何生成，不使用渲染网格自动碰撞，避免门洞被隐藏三角形堵住。
- 首版不生成屋顶、窗户、楼梯或多层结构。
- 生成与资源转换完全离线，不加载远程模型或脚本；参数和导出数据继续经过版本化 schema 校验与 SHA-256 配对。

## 验证

- 单元测试验证任意房间不再带固定 prefab、圆角模块闭合、门洞不重叠直墙、宽门为双扇且朝房内打开。
- 构建测试验证视觉包来源全部位于 `kenney_building-kit`。
- 浏览器检查圆角、走廊墙方向、门通行和顶点色。
- 重新生成固定 GLB/JSON，并运行 Godot 4.6 无头导入测试。
